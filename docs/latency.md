# 延迟测量

## 为什么要用相机

程序内埋点只能测到 `capture_ts_ns → present`，也就是"采集到呈现"。它漏掉了：

- 显示器扫描输出到人眼看到（B 端）
- 人眼看到到显示器响应（A 端）

这两段在 120 Hz 下合计 10–16 ms，占目标延迟的一半。所以必须测 glass-to-glass。

## 方法

1. B 端全屏显示一个毫秒计时器（浏览器 `performance.now()` 足够）
2. A 端全屏显示收到的画面
3. 用 240 fps 以上的手机同时拍两块屏幕
4. 逐帧读两个计时器的差值

## 判据

| 指标 | 目标 |
|---|---|
| 中位延迟 | ≤ 25 ms |
| p99 延迟 | ≤ 35 ms |
| 30 分钟卡顿次数 | 0 |

## 常见异常

| 现象 | 原因 |
|---|---|
| 延迟稳定但偏高 15 ms | 呈现走了 vsync，或交换链不是 flip model |
| 周期性 30 ms 尖峰 | 发送端没有限速，整帧突发打满队列 |
| 延迟缓慢漂移上升 | 抖动缓冲没有自适应收缩 |
| 偶发花屏后恢复 | FEC 组太大，或 NACK 未生效 |
