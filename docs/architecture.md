# 架构

## 拓扑

```
B（采集端 / 游戏机）                        A（接收端 / 推流机）
┌──────────────────────────┐               ┌──────────────────────────┐
│ 采集 WGC / DDAPI          │               │ 抖动缓冲                  │
│   ↓ GPU 纹理              │               │   ↓                      │
│ 色彩转换 BGRA → NV12      │   UDP 5000    │ FEC 恢复 / NACK          │
│   ↓                       │ ────────────→ │   ↓                      │
│ 编码 NVENC HEVC           │               │ 解码 NVDEC / D3D11VA      │
│   ↓ 码流                  │   UDP 5001    │   ↓ NV12 纹理             │
│ 切片 + FEC + 限速发送      │ ←──────────── │ 控制通道（请求 IDR 等）    │
└──────────────────────────┘               └──────────────────────────┘
```

B 只编码一次（高质量、高码率），A 负责分发到三个消费者：

| 消费者 | 帧语义 | 说明 |
|---|---|---|
| 呈现 | 只显示最新帧，旧帧直接丢 | 延迟优先 |
| 录制 | 一帧都不能丢 | 直接 remux 收到的码流，零转码 |
| 推流 | 一帧都不能丢 | A 端二次编码为 1080p60 @ 6 Mbps |
| 分析 tap | 忙则丢帧 | 下游 CV/OCR，允许跳帧 |

**这三种丢帧语义完全不同，必须用三条独立队列，不能共用一个。** 这是本项目最容易设计错的地方。

## 线程模型

| 线程 | 职责 | 队列 |
|---|---|---|
| capture | 等帧、取纹理、交给转换 | → convert |
| convert | compute shader 色彩空间转换 | → encode |
| encode | NVENC 异步编码 | → packetize |
| send | 打包、FEC、限速、发送 | → 网络 |
| recv | 收包、FEC、重组 | → decode |
| decode | NVDEC | → present / record / stream |
| present | 交换链呈现 | — |

所有跨线程队列使用 `SpscRing`（无锁单生产者/单消费者）。管线中不允许出现互斥锁——120 fps 下任何一处加锁都会变成可观测的抖动源。

## 关键参数

### 编码（NVENC HEVC）

| 参数 | 值 | 原因 |
|---|---|---|
| preset | P1 | 最快 |
| tuningInfo | ULTRA_LOW_LATENCY | 关掉内部缓冲 |
| frameIntervalP | 1 | 禁 B 帧 |
| gopLength | INFINITE + intraRefresh | 避免周期性整帧卡顿 |
| rateControl | CBR | 稳定码率，便于限速 |
| **vbvBufferSize** | **bitrate / fps** | **1 帧缓冲，默认值会攒 2-3 帧** |
| sliceMode | 3（每帧 N 片） | 降低单包丢失影响面 |

### 传输

- 载荷 1200 字节，包头 32 字节，总 1232，低于 1500 MTU
- FEC：每 16 个数据包 1 个 XOR 校验包（约 6.25% 开销）
- NACK：缺包 3 ms 后请求重传，发送端保留 200 ms 环形缓冲
- 限速：令牌桶，1 ms 粒度，burst 上限 1 ms 流量

## 延迟预算（1440p120）

| 环节 | ms |
|---|---|
| 采集 | 0–8.3 |
| 色彩转换 | 0.3 |
| 编码 | 3–5 |
| 打包 + 限速 | 0.5–1 |
| 网络 | 0.5 |
| 抖动缓冲 | 8–12 |
| 解码 | 2–3 |
| 呈现 | 0–8.3（tearing 时接近 0） |
| **合计** | **中位约 22 ms，p99 目标 ≤ 35 ms** |

延迟必须用高速相机拍两块屏幕上的毫秒计时器测量。程序内埋点只能测到"采集→呈现"，测不到 glass-to-glass，两者能差 15 ms。

## 采集后端选择

| 后端 | 优点 | 缺点 |
|---|---|---|
| **DXGI Desktop Duplication**（当前） | 纯 COM、有脏矩形、全屏独占稳定 | 不能按窗口采集、HDR 需额外处理 |
| Windows.Graphics.Capture | 支持窗口采集、API 更现代 | 依赖 C++/WinRT、无脏矩形 |

M0 先用 DDAPI 打通链路，M2 之后按需补 WGC 后端（同一 `ICaptureSource` 接口）。
