# 合规说明

## 本项目做什么

把**已授权设备**的屏幕内容，经局域网低延迟传输到另一台机器显示、录制或推流。

典型场景：游戏机 + 推流机、远程协助、多机工作流、大屏监控。

## 本项目不做什么

| 不做 | 原因 |
|---|---|
| 注入目标进程 | 修改他人进程属于明确的越界行为 |
| Hook D3D / DXGI 图形 API | 同上，且是反作弊的典型检测面 |
| 读取游戏/应用内存 | 与屏幕采集无关，且越界 |
| 规避 DRM / HDCP / WDA | 技术保护措施，绕过属违法风险 |
| 隐藏进程、伪装特征 | 用于规避检测的工具本身即不合规 |
| 把采集结果回写为游戏内自动决策 | 这是"作弊"与"工具"的分界线 |

## 设计上的合规约束

1. **采集走系统公开 API**（DDAPI / WGC），不使用任何注入或 hook 手段
2. **受保护内容如实失败**：遇到 DRM / WDA 保护，返回黑帧并上报，不尝试绕过
3. **被采集端知情**：托盘图标常驻，可一键停止，操作有本地日志
4. **默认不落盘、不上云**：仅局域网直连；录制需用户显式开启
5. **传输加密**：局域网内也使用 AES-GCM，避免同网段嗅探
6. **代码可审计**：MIT 许可，发布版提供签名

## 使用者的责任

- 采集他人屏幕前必须取得对方同意
- 遵守目标软件的服务条款与所在地法律
- 录制内容若含他人个人信息，需按当地隐私法规处理

## 边界

判断一个屏幕采集工具是否合规，看两点：

1. **采集的是谁的屏幕** —— 自己/已授权，还是他人未授权
2. **画面交给谁用** —— 人眼观看，还是程序自动参与第三方系统内的决策

技术栈本身是干净的，性质由这两点决定。
